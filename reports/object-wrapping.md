# HWP 개체 배치 규격 적용 — T-014

## 근거와 범위

제공된 한글문서파일형식 5.0 revision 1.3(2018-11-08)의 표 69·70을 대조했다. 공통 개체 속성의 bits 21–23은 0 Square, 1 Tight, 2 Through, 3 TopAndBottom, 4 BehindText, 5 InFrontOfText다. 기존 코드는 1을 자리 차지로 처리하고 나머지를 float로 묶었다.

이번 변경은 HWP 공통 개체 속성과 두 형식이 사용하는 표 분할 계산에 한정한다. KS X 6101:2024 링크는 후속 HWPX 대조 대상이며, 본 변경을 그 표준 전체의 구현으로 간주하지 않는다. 제공 문서 및 스크린샷은 저장소에 포함하지 않는다.

## 변경과 결정

- 배치 enum, signed 좌표, 기준 영역, 정렬, 글 흐름 방향, z-order와 원본 바깥 여백을 보존한다. 고정 2/6/10px 여백과 개체 여백을 무조건 지우는 처리를 제거했다.
- inline 우선순위를 유지하고 자리 차지는 본문 블록, 글 앞·뒤는 별도 겹침 배치로 처리한다. 원본이 의도한 겹침·음수 위치는 임의로 잘라 숨기지 않는다.
- 겹침 개체의 scrollHeight를 본문 높이로 세지 않으며 해당 표를 본문 분할 대상으로 선택하지 않는다. 분할 완료 후 실제 용지·본문·문단 영역에서 위치를 계산한다.
- 중첩 개체는 부모 깊이부터 배치한다. 부모 이동을 자식 좌표에 중복 적용하던 검토 발견 사항을 해결했다. 같은 깊이에서는 측정과 쓰기를 나눈다. 페이지 번호 목록을 개체마다 조회하지 않는다.
- 표만 있는 문단은 flow-root로 바깥 여백과 float 높이를 포함한다. 가용 폭은 원본 좌우 여백을 빼고 계산한다. 각 분할 조각의 앞·뒤 공간도 행 배치에 포함한다. 문서별 보정값·문자 압축은 추가하지 않는다.

## 검증

Chrome, Node 22.17.0. 별도 빌드/lint/typecheck 단계가 없는 단일 HTML 프로젝트로, `npm test`가 인라인 JavaScript 구문과 독립 실행 구조를 확인한다.

- `npm test`
- `npm run test:simplification`
- `npm run test:layout`
- `npm run test:fidelity`
- `npm run test:fonts`
- `npm run test:font-reflow`
- `npm run test:fields`
- `npm run test:document`
- `npm run test:objects`
- `node tests/containment.cjs --sample /path/to/sample` — 제공 HWPX/HWP 각각 검사
- `node tests/viewer.cjs --sample /path/to/sample.hwpx --sample /path/to/sample.hwp`

모두 통과. 새 합성 검사는 0–5 값, inline 우선순위, 비대칭 원본 여백, 글 흐름 방향, signed 좌표, 종이/본문/문단 기준, 중첩 배치, 반복 배치, 겹침 개체의 높이 제외, 조각별 표 여백을 확인한다. 0–2 검사는 사각형 근사 정책을 확인하는 것이며 윤곽 둘러싸기 정확도를 보장하지 않는다.

실제 인천 HWPX는 화면/PDF 9쪽. 교육 HWP는 이전 18쪽에서 화면/PDF 19쪽으로 변경되었다. 원본 여백을 포함한 분할로 자격종목 표의 마지막 주석 행이 반복 제목과 함께 다음 쪽에 배치된다. 75–200% 확대와 인쇄에서 글자·표·셀 경계 검사를 통과했고, 변경 전 본문 문자가 같은 순서로 유지됨을 확인했다(추가 문자는 반복 표 제목). 후반부 17–19쪽 화면도 확인했다. **19쪽이 원본과 정확히 같은 쪽 수라는 의미는 아니다.** 글꼴·줄 폭 차이에 따른 재배치는 남아 있다.

## 검토와 보안

별도 AI 읽기 전용 검토에서 중첩 배치 오류를 발견해 수정하고 재현 검사를 추가했다. 변경 범위에서 Critical/High 보안 문제는 발견되지 않았다. 새 외부 요청·의존성·실행 코드 입력·HTML 문자열 삽입은 없다. 개체 속성은 파서의 숫자 값으로 생성하며 짧은 선택 필드는 길이를 확인한다. 전체 파서 보안 감사나 취약점 부재의 보증은 아니다.

## 남은 제한

- Tight/Through 윤곽 둘러싸기, 가운데 float 배치는 사각형/좌측 근사다.
- 표만 있는 문단은 안정적인 표 분할을 위해 블록 영역을 소유한다. 다음 문단이 그 표 옆을 감싸는 배치는 아직 구현하지 않았다. 개체의 여섯 배치 값을 구분하는 것과 완전한 둘러싸기 엔진은 다르다.
- 다단 기준 영역은 현재 단일 본문 영역으로 근사한다. 상대 크기, 복잡한 도형 변환, HWPX의 공통 개체 모델 통합은 후속 범위다.
- 후반부 화면에서 날짜 등 일부 셀 내부 글자 겹침이 여전히 보인다. 경계 검사는 셀 밖 넘침을 확인하며 문자 사이 겹침까지 보장하지 않는다.
- 이미지 로드 지연에 따른 위치 재계산, 원본 글꼴 부재, 복잡한 병합 행/셀 분할의 정확성은 별도 검증이 필요하다.

## 배포와 복구

검증한 변경을 main에 푸시하면 GitHub Pages가 갱신된다. 배포 후 제공 두 문서를 다시 열어 화면/PDF 9/19쪽, 본문 유지, 브라우저 오류 없음과 배포 HTML 일치를 검사한다. 실제 배포 결과는 작업 로그에 기록한다.

복구는 이 변경 커밋을 `git revert <commit>`하여 main에 푸시하고 이전 HTML 배포를 확인하는 방식이다. 이전 정상 기준은 82904cbaa77ca15a3e2872c4dcbbdd11c55f033f이며 데이터/DB 마이그레이션은 없다. 복구 대상 커밋과 내용을 로컬에서 확인했으며, 실제 서비스 롤백은 실행하지 않았다.
